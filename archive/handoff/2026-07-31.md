## 1. 任务目标

做一个「观点回测」闭环，解决用户的真实工作流：

> 读微信公众号文章 → 分享到腾讯 **ima** 并让 ima 结合市场分析、给出投资意见 → 把对话**保存到 ima 知识库** → **fund-assistant 自动取回这份投资意见，结构化、按日回看、并做回测验证准不准**。

拆成三个能力：

1. **录入**：从 ima 知识库同步 / 粘贴链接（经 ima 抓取）/ 直接粘文本 → 抽成结构化「投资方向」卡片，并快照当日市场。
2. **回看**：按日期（月历）浏览历史观点与方向卡片，可看 ima 完整分析全文。
3. **回测**：对历史方向做 **T+5** 命中率与收益统计（买中涨 / 卖中跌 = 命中）。

### 两个关键设计决策（别推翻，是反复确认过的）

- **双输入形态**：ima 返回的内容**可能已经是「结合市场 + 观点」的成品分析**。这种情况只做轻量方向抽取（`mode="ima-analyzed"`，**不重跑 AI**，省 token 也避免二次曲解）；只有原始文本才跑完整 `callAI`（`mode="raw-text"`）。两条链路都收敛到同一个 `directions[] + fullText` 结构。
- **ima 只做「取数源」**：ima OpenAPI **读不到会话历史**，只能读知识库。所以前提是用户在 ima 侧把对话「保存到知识库」。不做生成式分析、不碰 ima 笔记。

### 2.3 核心口径（改代码前先理解）

**回测判定**（`insightBacktest.ts` 顶部注释即规范）

- 取观点日 T 到 T+5 的日 K（`KLINE_BACK = 400` 根，`HOLD_DAYS = 5`）。
- `buy` 且收益 > 0 → 命中；`sell` 且收益 < 0 → 命中。
- `hold` 计中性，**不计入**命中率。
- 取数缺口（无 T / T+5 数据，或 T+5 尚未发生）→ 标 `gap`，**排除出统计**，UI 用黄色标记。
- **按需计算、不写回原记录**（避免重复覆盖与数据陈旧）。

**ima API 契约**（踩过坑，见 §5）

- Base：`https://ima.qq.com`，路径前缀**必须** `/openapi/wiki/v1/`。
- 认证是**自定义 Header**，不是 Bearer：`ima-openapi-clientid` + `ima-openapi-apikey` + `Content-Type: application/json`。
- 成功判定 `code === 0`；`401` → 鉴权失败。
- 用到的端点：`get_addable_knowledge_base_list`（连通性探测）、`get_knowledge_list`（列举 KB 媒体）、`get_media_info`（笔记类直接带 `note_content`；网页类返回 `url_info.url` 需二次 fetch）、`import_urls`（`knowledge_base_id` + `folder_id` 均必填，URL 上限 1–10）。

## 5. 踩过的坑（血泪，务必先读再动手）

### 5.1 工具链 / 校验（最容易浪费时间的）

- **`husky` 的 `tsc --noEmit` 实为 no-op**。它跑的是仓库根 `tsconfig.json`——solution 风格（`files: []` + references），非 build 模式 → 只编译空 files 集，**恒 0 error**。真正兜底的是 `eslint`（仅暂存文件）+ `vite build`。
- **全量 `tsc -p tsconfig.app.json` 有 40+ 预存 error**（TS 6.0.3 + `erasableSyntaxOnly` 禁 enum、`verbatimModuleSyntax` 下的类型问题等），是**历史遗留工具链问题，不是你改出来的**。
  → 正确姿势：`tsc --noEmit -p tsconfig.app.json 2>&1 | grep -E "<你改的文件>"`，只看自己那几个文件，别被洪水淹没。
- **`tsc` 退出码陷阱**：别写 `tsc ... | head` 然后看 `$?`——那是 `head` 的退出码（恒 0），会掩盖真实失败。要么直接 `tsc --noEmit; echo "$?"`，要么用 grep 看内容。
- **所有 node/npx 命令必须带 `NODE_OPTIONS=""` 前缀**；`npm install` 用 `--force` 绕 peer dep 冲突。
- Bash 工具每条命令 cwd 会重置，需要显式 `cd`。

### 5.2 本轮新踩的

- **`formatDateOnly(ts: number)` 收的是时间戳数字，不是 `Date` 对象**。传 `new Date()` 会报类型错。本轮在 `InsightInputView` / `InsightTimelineView` 各踩一次。
- **Dexie `.upgrade()` 不覆盖全新库**（详见 §4.1）。凡是「首启预置数据」都必须同时挂 `on("populate")`，否则只有老用户有数据、新用户没有——这种 bug 在本地开发时几乎发现不了，因为你的库早就是升级上来的。
- **`interface` 体内不能写 `export type` / `export interface`**，类型声明必须放模块顶层，否则 husky 直接拦。
- **ima API 前缀**：必须 `/openapi/wiki/v1/`，用旧的 `/wiki/v1/` 或 `/api/v1/` 会 401；认证是自定义 header 不是 Bearer——这两点各坑过一次。

### 5.3 项目既有的重要约束（历史积累）

- **`stock-sdk` 是第三方只读依赖**（`github.com/chengzuopeng/stock-sdk`），**不能改也不能 push**。本项目只是它的 npm 消费方，唯一可维护的仓库是 `fund-assistant`。任何「去上游补一下」的念头都不成立（无权限）。
- **CORS 现实**：本项目是浏览器 SPA，直连 `*.eastmoney.com` 等会被 CORS 拦。Cloudflare Worker 是**CORS 反代**（服务端代抓回传），跟「东财通不通」是两回事——网络能通，CORS 照样拦。
- 不手写东财 / 腾讯的 fetch + 解析，优先用 `stock-sdk` / `stock-api` 已覆盖的能力。（例外：本轮 `insightMarket.ts` 复用了项目既有的 `fetchTencentKline`，那是早已存在的适配器，不是新写解析。）
- **`stock-sdk` 门面方法名是「简名」**：如 `sdk.calendar` 暴露 `marketStatus` 而非 `getMarketStatus`；市场参数枚举是 `'A' | 'HK' | 'US'`（A 股用 `'A'`，**不是 `'CN'`**）。
- **`sdk.report` 在已发布的 v2.4.0 里是 `undefined`**（研报 service 未发版），调用会崩页面，需要守卫。
- **`vite-plugin-pwa` 用 `injectManifest` 策略时**，`maximumFileSizeToCacheInBytes` / `globPatterns` 必须写在 **`injectManifest` 键**下，写在 `workbox` 键下完全不生效（默认 2MiB 上限会让 2.3MB 的主包构建失败）。且该版本 schema **拒收** `cleanupOutdatedCaches` / `navigateFallback` / `runtimeCaching`（generateSW-only）。
